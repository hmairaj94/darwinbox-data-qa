# Approach and key decisions

I built the prototype around a deliberate separation: the language model decides *what analytical query to run*, while deterministic code controls *what data exists, what SQL is permitted, and how results are displayed*. FastAPI serves a minimal upload/chat interface. Pandas reads CSV and every Excel sheet, normalizes identifiers, profiles columns, and loads each table into a session-specific DuckDB database. A small metadata registry records types, samples, null rates, and likely cross-file joins. Join hints combine column-name similarity with sampled value overlap, which gives the model grounded alternatives instead of asking it to guess relationships.

The orchestration is a custom, function-based LangGraph state machine using ChatGroq and a Groq-hosted open model. It is intentionally not a generic ReAct agent. An `agent_node(state, config)` chooses a tool; the router injects trusted session context into hidden tool arguments and routes to a dedicated schema or SQL node. A post-processor converts the SQL tool's JSON output into graph state, then conditional edges send failures through a bounded repair loop and successful results to answer synthesis. This makes control flow visible, testable, and finite.

Safety is layered. Only one parsed `SELECT`/query expression is accepted, every referenced table must belong to the current upload session, external reader functions are blocked, DuckDB is opened read-only for questions, and result rows are capped. The frontend renders values as text, not HTML. Chart selection is deterministic: suitable categorical/numeric results become bar charts and time/numeric results become line charts when the question calls for a visual. The model emits neither JavaScript nor an unchecked chart specification.

The key trade-off is scope. Session files and metadata stay on local disk, there is no login, and pandas loads uploads in memory. This is appropriate for a 4–6 hour prototype and keeps the behavior easy to demonstrate. Given more time, I would add a clarification branch for ambiguous joins, session expiry and authentication, streaming ingestion to Parquet, query cancellation/timeouts, richer evaluation fixtures for NL-to-SQL accuracy, and object storage plus a persistent metadata database for horizontal deployment.
